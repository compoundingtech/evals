# vrs-command-policy-demo

This designed-to-pass demonstration gives one Claude Sonnet 5 medium worker a
realistic multi-file launcher task with several plausible implementations. The
task asks for an end-to-end policy feature without enumerating the shell,
structured-data, byte-identity, or subject-selection constraints. Those
architectural constraints exist only in the fixture's protected requirements
and living specification.

Eight blind executable judges cover hostile-byte generation, policy failures,
command boundaries, unaffected task classes, runnable evidence,
mutation-validity across both implementation seams, coupling, and repository
isolation. No judge scores requirement IDs, citations, or prose.

Run the free oracle/mutation proof with:

```sh
bin/check-vrs-complex.sh
```

Run the paid cell only under a reviewed provider gate:

```sh
st2 eval ./cells/vrs-command-policy-demo/ --keep
```
